# HTTP 的请求、响应与会话

HTTP 即超文本传输协议，是客户端与服务器交换网页资源的应用层协议。浏览器通常作为客户端，向服务器请求文档、图片或其他资源；服务器接收请求后返回响应。展示一个完整网页，往往需要先获取主要文档，再获取样式、脚本、图片等附属资源，因此一次打开网页可能对应多次请求。

HTTP 请求通常包含请求方法、资源路径、协议版本、标头和可选的消息体。请求方法说明客户端希望执行什么操作，例如 GET 常用于获取资源，POST 常用于向服务器提交数据。请求路径指出目标资源的位置。标头提供额外信息，消息体则在需要时携带提交的内容，并不是所有请求都必须包含消息体。

HTTP 响应通常包含协议版本、状态码、标头以及可选的响应体。状态码说明请求处理的结果，例如是否成功，或者出现了什么问题。响应体可以承载返回的网页或数据。读取响应时，需要区分用于描述处理结果和附加信息的标头，以及真正作为内容传输的消息体。

HTTP 本身具有无状态性，即两个成功请求之间并不天然共享应用状态。不过，无状态不等于网站不能维持会话。网站可以借助 Cookie 等机制，在多次请求之间建立联系，使购物车、登录状态或其他连续交互得以实现。会话是通过附加机制组织起来的，而不是因为每次 HTTP 请求都自动记住之前的请求。

浏览器和最终服务器之间还可能存在代理。代理可以提供缓存、访问过滤、负载均衡、认证或日志记录等功能。服务器也不一定是一台物理机器，它可能由多台机器共同分担请求。HTTP 标头使协议能够扩展，也能用于控制缓存、认证和跨来源访问等行为。

HTTP 的语义与消息的底层传输形式应当区分。早期版本的消息通常可直接以文本理解，而 HTTP/2 使用二进制帧组织消息，并通过多路复用提高连接利用率。请求方法、状态码和标头等概念仍然存在。理解请求和响应的组成，是排查网页资源获取问题和阅读网络日志的基础。
